# Report Header Metadata Reference

[Back to project README](../README.md) | [Getting Started](GettingStarted.md) | [Metadata Configuration Guide](MetadataConfigurationGuide.md) | [`tblReportSequence` Reference](TblReportSequenceReference.md) | [Troubleshooting](Troubleshooting.md) | [Medicare Pipeline](WorkedExamples/MedicarePipeline.md)

## Purpose

`tblGoodFieldName_Header` defines the one-time worksheet header area that appears above the repeating report bands. It is separate from the metadata used for grouped report sections and grand totals.

The four related metadata layers are:

```text
tblGoodFieldName_Header
    -> one-time worksheet header

tblGoodFieldName_Report
    -> repeating grouped report bands

tblGoodFieldName_G_Totals
    -> one-time report-level grand-total block

tbl_temp_sorting_grouping
    -> calculated physical row coordinates for report bands
```

The Medicare demo uses `tblGoodFieldName_Header` to create a title area, a public-source hyperlink, a demonstration subtitle, generated-report information, merged ranges, colors, fonts, borders, row heights, and a freeze-below setting.

## 1. Why the Header Is a Separate Metadata Layer

The repeating H1 zone in `tblGoodFieldName_Report` belongs to each grouped band. The worksheet header is different because it appears once at the top of the sheet.

```text
Worksheet header
    appears once
    controlled by tblGoodFieldName_Header

Grouped H1 header
    appears once per report band
    controlled by tblGoodFieldName_Report
```

This distinction prevents worksheet-level content from being repeated for every RBCS band or KPI month.

## 2. Medicare Header Example

The current Medicare configuration includes the following visible content:

```text
Medicare Report for Texas, 2024 Data.

Medicare Physician & Other Practitioners - by Provider and Service

Metadata Reporting Engine Demonstration

Report Generated by A.F.

Report Generated at: <current date and time>
```

The public-source line is produced with an Excel `HYPERLINK` formula. The generated-time line uses `NOW()` and `TEXT()` in an Excel expression.

## 3. Record Selection and Ordering

### `Sort`

Controls processing order within the header metadata.

Use unique, sequential values where practical.

### `Report`

Identifies the workbook definition.

Medicare example:

```text
Medicare_Report.XLSX
```

This must match the report identifier used by the rendering workflow.

### `Tab`

Identifies the target worksheet.

Medicare example:

```text
Medicare_Report
```

### `Letter`

Identifies the Excel column associated with the metadata record.

The Medicare configuration contains records for columns `B` through `R`.

### `Active_YN`

Indicates whether the header metadata record is active. Use the same Access Yes/No representation used by the working configuration.

## 4. Item-Level Header Fields

Fields ending in `_H1_A` describe an individual worksheet-header item.

### `ColorIndex_H1_A`

Specifies the item's fill or theme color configuration.

The Medicare metadata includes `xlThemeColorDark2` on several header records.

### `Row_Height_H1_A`

Specifies the row height associated with an individual header item.

The Medicare title configuration includes a row height of `20.25`.

### `FieldName_H1_A`

Stores the visible text or label for the header item.

Examples from the Medicare configuration:

```text
Medicare Report for Texas, 2024 Data.

Report Generated by A.F.
```

### `HeaderRow_H1_A`

Specifies the worksheet row used by the individual header item.

The Medicare configuration places different header elements on different rows near the top of the worksheet.

### `Range_H1_A`

Stores an Excel formula or expression associated with the item.

Medicare examples include:

```excel
HYPERLINK(
    "https://data.cms.gov/provider-summary-by-type-of-service/medicare-physician-other-practitioners/medicare-physician-other-practitioners-by-provider-and-service/",
    "Medicare Physician & Other Practitioners - by Provider and Service"
)
```

and:

```excel
"Report Generated at: " & TEXT(NOW(),"mm/dd/yyyy h:mm AM/PM")
```

Store expressions using the convention expected by the renderer. Test formulas in a small workbook before publishing a new header configuration.

### `Font_H1_A`

Specifies the item font.

The Medicare configuration uses `MS Sans Serif` for visible title items.

### `Font_Size_H1_A`

Specifies the item font size.

The Medicare title and generated-by content use size `15` in the supplied metadata.

### `Font_Style_H1_A`

Specifies the item font style.

The Medicare configuration uses `Bold`.

### `Font_Color_H1_A`

Specifies the item font color.

The Medicare configuration uses `Black`.

### `Format_H1_A`

Specifies the Excel number format or display format for the item.

The Medicare title uses `General`.

### `Wrap_Text_H1_A`

Controls text wrapping for the individual header item.

### `Underline_H1_A`

Controls underlining for the individual header item.

### `MergeRange_H1_A`

Specifies the merge range for an individual header row. The `?` token represents the configured header row.

Medicare examples:

```text
C?:D?
Q?:R?
```

If the item is assigned to row 2, `C?:D?` resolves conceptually to:

```text
C2:D2
```

### `LineWeight_H1_A`

Specifies border weight for the individual item.

### `LineTop_H1_A`

Controls the top border.

### `LineBottom_H1_A`

Controls the bottom border.

### `LineLeft_H1_A`

Controls the left border.

### `LineRight_H1_A`

Controls the right border.

### `LineVert_H1_A`

Controls vertical border behavior within the configured range.

## 5. Shared Header-Row Fields

Fields ending in `_H1` without the item suffix describe broader header-row or shared-range formatting.

### `HeaderRow_H1`

Specifies the worksheet row for the shared header configuration.

### `Font_Size_H1`

Specifies the shared header font size.

The Medicare metadata includes values such as `11` and `13` for shared header content.

### `Font_Style_H1`

Specifies the shared header font style.

The Medicare configuration uses `Bold`.

### `Font_Color_H1`

Specifies the shared header font color.

### `MergeRange_H1`

Specifies a broader merged range for worksheet-header content.

Medicare example:

```text
C?:R?
```

### `ColorIndex_H1`

Specifies the shared header fill color.

The Medicare configuration includes the numeric color value `65535`.

### `Row_Height_H1`

Specifies the shared header row height.

The Medicare configuration includes a value of `25`.

### `Range_H1`

Stores shared worksheet-header text or an Excel expression.

Medicare examples:

```text
"Metadata Reporting Engine Demonstration"
```

```excel
"Report Generated at: " & TEXT(NOW(),"mm/dd/yyyy h:mm AM/PM")
```

### `LineWeight_H1`

Specifies border weight for the shared header range.

The Medicare configuration includes `Thin`.

### `LineTop_H1`

Controls the shared top border.

### `LineBottom_H1`

Controls the shared bottom border.

### `LineLeft_H1`

Controls the shared left border.

### `LineRight_H1`

Controls the shared right border.

### `LineVert_H1`

Controls vertical borders inside the shared range.

### `FreezeBelow_YN`

Marks the header definition that controls freezing below the worksheet-header area.

Use this setting to keep the report header or headings visible while scrolling, according to the renderer's implemented freeze behavior.

## 6. Header Zones in the Medicare Worksheet

The metadata demonstrates several worksheet-header roles.

### Main title

```text
Medicare Report for Texas, 2024 Data.
```

The title uses a dedicated header row, larger bold text, a merge range, and item-level formatting.

### Public data-source hyperlink

```text
Medicare Physician & Other Practitioners - by Provider and Service
```

The visible hyperlink text is generated by an Excel `HYPERLINK` expression and points to the CMS source page configured in the metadata.

### Demonstration subtitle

```text
Metadata Reporting Engine Demonstration
```

This uses a broader merged range spanning much of the visible report area.

### Generated-by label

```text
Report Generated by A.F.
```

This is positioned toward the right side of the worksheet header.

### Generated timestamp

```excel
"Report Generated at: " & TEXT(NOW(),"mm/dd/yyyy h:mm AM/PM")
```

The timestamp is calculated by Excel when the workbook is recalculated.

## 7. Relationship to Reserved Worksheet Rows

The renderer must reserve enough rows above the first report band for the worksheet header.

The worksheet-header area and the grouped-report area should not overlap:

```text
Worksheet rows reserved for tblGoodFieldName_Header
    -> worksheet title, source link, subtitle, generated information

First grouped report band
    -> H1, B, B_D, F1, and F2 zones
```

When adjusting the worksheet starting position, validate both the header and the first generated report band.

## 8. Recommended Configuration Workflow

1. Copy a working header configuration.
2. Change `Report` and `Tab` to the new identifiers.
3. Keep `Sort`, `Letter`, and row assignments intact initially.
4. Replace visible text and formulas.
5. Confirm every merge range is valid.
6. Render with a small dataset.
7. Verify the first report band begins below the header.
8. Verify the freeze position after reopening the workbook.

## 9. Validation Checklist

### Identification

- [ ] `Report` matches the active report identifier.
- [ ] `Tab` matches the target worksheet.
- [ ] `Sort` values are ordered.
- [ ] `Letter` values contain valid Excel columns.
- [ ] Only intended records are active.

### Content

- [ ] Static title text is correct.
- [ ] Formula expressions are valid Excel expressions.
- [ ] The public-source hyperlink points to the intended source.
- [ ] The generated timestamp recalculates.

### Layout

- [ ] Header rows do not overlap.
- [ ] Merge ranges use valid columns.
- [ ] Merged cells do not collide.
- [ ] Row heights are sufficient.
- [ ] Font and fill colors are readable.
- [ ] Borders appear on the intended edges.

### Integration

- [ ] The first grouped band begins below the worksheet header.
- [ ] Raw exported data is not overwritten by header content.
- [ ] Freeze-below behavior uses the intended boundary.
- [ ] The saved workbook reopens without repair warnings.

## 10. Common Problems

### Header does not appear

Check `Report`, `Tab`, `Active_YN`, and the renderer query that loads header metadata.

### Header appears on the wrong worksheet

Check the exact `Tab` value and confirm there are no leading or trailing spaces.

### Title is clipped

Increase `Row_Height_H1_A`, enable wrapping where appropriate, or widen the merge range.

### Hyperlink displays as plain text

Confirm the expression is being assigned as an Excel formula rather than written as a literal string.

### Excel formula contains a syntax error

Test the finished expression directly in Excel. Pay particular attention to doubled quotation marks when an expression is stored in Access.

### Merge operation fails

Check that the range is valid, that `?` resolves to an existing row, and that the target cells are not already part of an incompatible merged area.

### Header overlaps the first report band

Increase the reserved worksheet-header area or adjust the first report-band starting row. Do not use report-band header overrides as a substitute for worksheet-header space.

### Freeze position is wrong

Inspect the record using `FreezeBelow_YN` and verify the header row associated with that record.

## 11. How This Differs from `tblGoodFieldName_Report`

`tblGoodFieldName_Header` is worksheet-scoped and rendered once.

`tblGoodFieldName_Report` is group-scoped and rendered repeatedly.

```text
tblGoodFieldName_Header
    report title
    source hyperlink
    demonstration subtitle
    generated-by information
    generated timestamp
    worksheet freeze position

 tblGoodFieldName_Report
    group label
    column headings
    detail formatting
    formulas
    subtotals
    extended footers
```

Do not put one-time worksheet content into the repeating H1 metadata unless repetition is intentional.
